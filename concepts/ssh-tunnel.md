# SSH 隧道

SSH 隧道就是用 SSH 协议给其他 TCP 连接套上一层加密通道，把原本裸奔的流量变成加密流量，安全又隐蔽。

SSH 本身是一个加密的远程登录协议，默认端口 22。可以把它理解成先在本地电脑和远程服务器之间建立一条加密的 SSH 管道，再把其他应用的 TCP 连接"塞进"这条管道里走。

## 三种模式

### 1. 本地端口转发（最常用）
把远程服务器的端口映射到你本地电脑的一个端口上。

```bash
ssh -L 本地端口:目标地址:目标端口 远程用户@远程服务器
```

**实际场景**：通过公网服务器访问内网 NAS 的 SMB 共享
```bash
ssh -L 44500:192.168.31.187:445 root@124.221.132.29
```
之后访问 `\\127.0.0.1:44500` 即可用 SMB，全程加密。

### 2. 远程端口转发（反向隧道，内网穿透）
把本地内网的端口映射到远程服务器上。

```bash
ssh -R 远程端口:本地地址:本地端口 远程用户@远程服务器
```

### 3. 动态端口转发（SOCKS5 代理）
在本地创建一个 SOCKS5 代理，所有流量通过 SSH 隧道出去。

```bash
ssh -D 1080 远程用户@远程服务器
```
之后在浏览器/系统里设置 SOCKS5 代理 `127.0.0.1:1080` 即可安全上网。

## SSH 隧道 vs FRP 隧道

| 特性 | FRP 隧道 | SSH 隧道 |
|------|----------|----------|
| 加密 | 可选（默认明文，可开 TLS） | **默认全程加密** |
| 配置难度 | 要装 FRP 客户端+服务端 | **只要有 SSH 就能用，一条命令搞定** |
| 端口复用 | 支持多端口穿透 | 单条隧道可以做端口转发 |
| 适用场景 | 长期、多端口的内网穿透 | 临时、安全的端口转发 |

## 与其他协议的关系

- **HTTP/HTTPS**：网页后台，可读可写，代理兼容
- **SOCKS5**：纯全局 TCP 通道，万能中转
- **SSH 隧道**：最高级加密管道，远程改主机、修改系统文件，穿透能力最强
- **SMB**：原生硬盘直连协议，不走浏览器通道，不开代理
