## 2. Docker 镜像源归属说明

- 国内老牌正规云原生企业，CNCF 深度参与厂商
- 开源公共镜像同步项目 public-image-mirror，完全免费
- 支持 docker.io、gcr.io、ghcr.io、quay.io 等几乎所有海外仓库
- 两种用法：
  - 镜像加速源配置：`https://docker.m.daocloud.io`
  - 前缀替换拉取：`m.daocloud.io/docker.io/library/nginx`
- 稳定性、合规性强，企业、生产环境均可放心使用

### docker.1ms.run（毫秒镜像 / 1ms Mirror）

- 运营主体：木雷坞（mliev.com，俗称毫秒云，与宝塔面板深度合作）
- 独立第三方商业化镜像加速服务商
- 模式分层：免费通道仅开放 docker.io、ghcr.io；付费会员解锁 gcr、k8s、nvcr 等
- 国内 CDN 节点多，NAS（极空间/绿联）、宝塔面板内置推荐源
- 有商业付费业务支撑运维，存续更稳定

### 三者核心区别对比

| 服务 | 运营主体 | 定位 | 适用场景 |
|------|---------|------|---------|
| Docker Hub | Docker Inc（海外官方） | 原始镜像源 | 海外服务器、无网络限制环境 |

### 国内访问痛点与解决方案

- 直连海外服务器速度极低、频繁超时

## 3. Hermes Agent 国际版登录卡死问题

### 问题根因

- portal.nousresearch.com 海外域名国内无法直接访问
- 终端轮询认证链路的请求也被网络拦截
- 国际版（GitHub 原版）强制走 Nous Portal 海外 OAuth 登录

### 解决办法

**方案 A（继续用国际版）：** 配置终端全局代理（TUN 模式），在代理环境下手动打开授权链接

**方案 B（推荐，无需特殊网络）：** 执行 `hermes setup` 配置国内模型源（OpenRouter、智谱、Kimi、Ollama），跳过海外登录

**方案 C：** 换国内适配版 Trae CN（移除了强制 Nous Portal 登录逻辑）

### 关于路由器开放端口

端口映射解决的是"外网→内网"入站访问，而 Hermes 登录需要的是"内网→海外服务器"出站访问，二者无关。开端口无法解决。

### 关于路由器 VPN 方案

- 路由器刷 OpenWRT/梅林固件 → 装 Clash → 规则分流（国内直连、海外走代理）→ 全屋设备自动走代理
- 硬件门槛：路由器需支持刷第三方固件，或使用软路由（X86 小主机）

## 4. 路由器选购与软路由对比

### 可装插件的路由器品牌

- **华硕高端**（RT-AX86U、GT-AX6000 等）：原厂可开 SSH，刷梅林后完整软件中心一键装 KoolClash
- **GL.iNet**（MT3000、Beryl AX 等）：出厂原生 OpenWrt，自带完整软件包商店，不用刷机
- **小米新款**：原厂封闭，必须刷第三方 OpenWrt
- **华为/TP-Link/水星**：完全封闭，不支持装 Clash
- **X86 软路由**（N100、N5105、J4125）：终极自由，但需要搭配 AP 做 WiFi 覆盖

### 软路由 VS 硬路由对比

| 维度 | 华硕梅林硬路由 | X86 N100 软路由 |
|------|--------------|----------------|
| Clash 智能分流性能 | 千兆加密勉强跑满，多插件易满载 | 2.5G 带宽加密无压力 |
| WiFi | 自带高端无线，信号强 | 无 WiFi，需搭配 AP |
| 功耗 | 8~15W | 15~30W |
| 折腾上限 | 中等 | 极高（虚拟机、Docker、All in One） |
| 上手难度 | 低 | 偏高 |

### 推荐组网方案

**轻度用户（300~1000M 宽带）：** 华硕梅林 AX86U/BE86U 做主路由，一台搞定

**重度用户：** N100 软路由（主路由）+ 华硕 AP（仅做 WiFi 发射），性能天花板

## 5. PVE 虚拟化 All-in-One 方案

### 架构

```
光猫 → 物理服务器网卡1(WAN) → 虚拟机OpenWrt(软路由) → 网卡2(LAN) → AP路由器(仅WiFi) → 全屋设备
```

### 关键技术要点

- 网卡必须 PCIe 直通，不能用虚拟桥接（否则性能损耗）
- AP 必须改纯 AP 模式，杜绝双层 NAT
- 路由虚拟机建议预留 2 核 + 4G 内存封顶，保证稳定

### 风险与折中方案

All-in-One 的最大风险是宿主机单点故障（硬件崩了，路由+所有业务一起断）。建议方案：

- 独立华硕梅林做主路由（兜底上网）+ 大服务器仅跑业务/旁路由
- 或者至少做双电源、系统盘 RAID1

## 6. 虚拟机 CPU/内存分配原理

- **CPU：** 默认动态共享模式——你设的"2 核"是**峰值上限**，空闲算力其他虚拟机可用；只有手动物理核心绑定才会独占
- **内存：** 一旦分配占用就锁定不可回收；推荐路由开内存预留保障基础网络不因其他业务满载而断流
- **路由虚拟机：** 一定要开内存预留 + CPU 上限限制，避免业务虚拟机爆负载把路由挤崩

## 7. Sing-box inbound 解释

新增 inbound（如 172.17.0.1:1081）只是多开一个监听端口：
- 不影响已有出站代理节点、路由规则和其他监听端口
- 容器不会自动走代理——必须显式设置 `HTTP_PROXY`/`HTTPS_PROXY` 环境变量
- 这条通道是"闲置"的，不会主动接管任何容器流量
